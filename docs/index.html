01 / THE IDEA

A reading you can question.

01

What was calculated?

Show chart positions, birth-time uncertainty and the exact calculation conventions. An AI model does not calculate the planets.

02

What does the source say?

Open a permitted passage with its work, translator, edition and page or verse. Keep the original, commentary and interpretation distinct.

03

What is being inferred?

Explain how a traditional rule might apply, including exceptions and disagreement. Missing evidence leads to a limited answer, not invented certainty.

A correct chart and a faithful citation do not establish that astrology predicts future events. The product must preserve that distinction.

02 / HOW IT WORKS

One question. An inspectable path.

  1. Sign in & confirm inputs Google login, birth place and time precision
  2. Calculate the chart Versioned astronomical facts and settings
  3. Retrieve source passages Rights-cleared books, relevant rules and exceptions
  4. Explain & validate Bounded AI workflow; check claims and citations
  5. Read with context Facts, passages, interpretation and limitations

The proposed stack

Python + FastAPI for the application · Jinja2 + HTMX for the UI · PostgreSQL for accounts and records · Qdrant and local embeddings for retrieval · LangChain / LangGraph for bounded generation · Swiss Ephemeris after a licensing decision.

05 / HOW WE BUILD WELL

Small changes. Tests alongside them.

  1. Define one behavior. Keep each commit coherent and independently reviewable.
  2. Write a meaningful failing test. Then implement the smallest complete change.
  3. Test and review while building. Independent agents can inspect risky logic and test stable revisions in parallel.
  4. Verify the combined revision. Fix failures before dependent work; record commands and results.
  5. Earn release readiness. Documentation checks do not replace application, security or domain tests.
